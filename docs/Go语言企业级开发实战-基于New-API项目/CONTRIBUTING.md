# 贡献指南（Docs）

非常感谢你对本书的关注与贡献！为保持内容质量与一致性，请遵循以下约定。

## 基本流程
- Fork 仓库并创建分支（如 `docs/chapter-08-auth-revamp`）。
- 修改对应 Markdown 文件与资源。
- 本地预览（可选，推荐在 GitBook Space 预览）。
- 提交 PR，简要说明变更范围与动机，并勾选检查项。

## 目录与导航
- 导航文件：`SUMMARY.md`（侧边栏）与 `README.md`（书籍首页）。
- 新增/重命名章节后，务必同步更新 `SUMMARY.md` 与 `README.md` 中的目录列表。
- 链接一律使用相对路径，例如：`[第4章](./第4章-Gin框架入门与实战.md)`。

## 章节结构规范
- 顶部一级标题：`# 第N章 标题`（或 `# 附录X：标题`）。
- 二级标题用作子章节：`## N.M 子标题`，从 `N.1` 开始递增，保持升序，不得出现乱序（例如 `3.2/3.3/3.1`）。
- 章末固定包含三节，且按以下顺序：
  - `## 本章小结`
  - `## 练习题`
  - `## 扩展阅读`

## 图表与可视化
- 优先使用 Mermaid 图表（流程图、时序图、架构图等）概括关键流程或结构，放在章节导入或关键段落处。
- 代码块语法：
  - Flowchart：
    ```mermaid
    flowchart LR
    ```
  - Sequence：
    ```mermaid
    sequenceDiagram
    ```
- 图表下方添加图注：`图1：xxx`、`图2：yyy`，同一章按出现顺序递增。
- 如引用外部图片，请放置于同级 `assets/` 目录并用相对路径引用。

## 代码片段
- 示例代码应精炼、可运行或足以表达要点，避免冗长堆砌。
- 更长的实现建议以“片段 + 要点 + 参考链接”的模式呈现。
- 使用 Go 代码块标注：
  ```go
  // 示例
  ```
  其他命令或配置用合适的语言标注（`bash`/`yaml`/`json`）。

## 风格与校对
- 术语统一：如“渠道”“令牌”“负载均衡”“鉴权”等保持全文一致。
- 标点与中文排版：中英文之间留空格，数字与单位间留空格（如 `10 ms`）。
- 标题层级从大到小，不要跳级。

## 提交检查清单（PR 模板参考）
- [ ] 更新了 `SUMMARY.md`（如有新增/重命名章节）。
- [ ] 章节内子标题从 `N.1` 开始升序编号。
- [ ] 章末包含“本章小结 / 练习题 / 扩展阅读”。
- [ ] 图表添加了图注（图1/图2…）。
- [ ] 所有链接为相对路径并可访问。
- [ ] 代码示例已精炼且与主题相关。

## 许可证与署名
- 文档采用 CC BY 4.0（署名）协议，贡献内容将以相同协议发布；提交即视为同意以该协议授权。
- 请在 PR 中补充署名信息（GitHub ID 即可），我们会在致谢页或章节末尾合适位置注明。

感谢你的贡献！
